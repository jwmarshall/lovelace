Do not reclassify that accepted scope as ambiguous or demand authorization for each identifier. ## Method

1. **Map before editing.** Classify selected presentation, codebase-only rename or full cutover. Inventory actual current identity owners and all affected callers, modules, OTP/config, project-owned library/path/command/tooling/storage/keychain names, environment variables, tests and docs. Map old to target identifiers and identify obsolete paths. For affected presentation enumerate routes/states and M01–M12 applicability; for code-only changes mark visual rules not applicable with reasons. Record replaced identity/presentation versus preserved product/security behavior. Include lifecycle, account/generation fences, deep links and permission boundaries where affected. Untouched visual surfaces are not automatic migration failures.
2. **Reuse one foundation.** Integrate target values into existing owners; migrate all consumers of the selected decision rather than add a second theme/component system, specimen-sheet runtime dependency or compatibility alias. Use canonical identity/signal assets and local licensed fonts; never redraw an approximation or add a remote dependency. Shared-owner changes must remain bounded to the selected decision and identified affected callers. If that cannot be done within authority, report the precise scope conflict before expanding.
3. **Preserve production architecture.** Apply the authorized identity map across every affected module/OTP/config/path/command/tooling/keychain/storage/environment caller; remove obsolete aliases and discovery definitions, not compatibility shims. No users and replaceable data mean no rebrand-specific data migration or preservation requirement. Preserve Ash domain/action/policy ownership, public application capabilities, adapter direction, LiveView lifecycle, loopback/single-owner/session security, Lock versus idle, self-hosted assets, durable Oban work and account/generation fences. Never substitute study routing, fake totals or simulator persistence for real behavior. Resolve missing production designs explicitly.
4. **Compose existing development workflows.** For boundary changes load `monolith-architecture-development`; for async/admission/recovery changes load `monolith-oban-workflows`. If absent, record exact discovery failure and use current inspected project operational contracts plus the bundled architecture invariants; if those cannot establish the essential contract, return `[INSUFFICIENT DATA: Missing required rebrand context]`. Do not claim an unavailable skill ran or install it silently. No new framework, task bus, context, background primitive or provider work merely for styling.
5. **Complete the selected slice.** Implement every selected caller, accessible state, responsive mode and lifecycle transition. Preserve safe user input, security warnings and explicit action scope; delete only code made obsolete by this cutover within authorized paths. Update affected tests and existing UI/product docs to describe what actually migrated, not future whole-app MONOLITH behavior. Do not weaken tests, replace behavior with placeholders or hide unfinished work behind fallback aliases.
6. **Obtain source reviews.** For affected presentation invoke available native `monolith-visual-system-reviewer` for M01–M05 and visual M06/M07/M11/M12, and `monolith-experience-reviewer` for M06–M12 interaction/state/voice. Give each exact changed paths, scope/replacement map, approved source references and sanitized evidence; both are read-only source reviews, not browser certificates. Discover and use affected existing specialists: `monolith-liveview-ui-reviewer`, `monolith-security-privacy-reviewer`, `monolith-account-isolation-reviewer`, `monolith-hexagonal-boundary-reviewer`, `monolith-background-work-reviewer`, `monolith-integration-reliability-reviewer`, `monolith-ash-sqlite-reviewer`, `monolith-test-reliability-reviewer`, and `monolith-cross-file-reviewer` as applicable. Preserve delegation authority limits. If native invocation is unavailable, inspect the installed portable counterpart if available and explicitly label any caller-performed review `PORTABLE FALLBACK — not native invocation`; do not fabricate native completion. If neither can provide essential review, return `[BLOCKED: Reviewer unavailable]`.
7. **Exercise applicable acceptance.** For codebase-only identity changes prepare inspected namespace/caller/path/config/command checks and relevant synthetic behavior tests; browser/contrast proof is not a gate when presentation is unaffected. For affected presentation use `monolith-design-verification` if available, otherwise the bundled applicable runtime rules in a safe synthetic browser; missing discovery is disclosed, not a waiver. Inspect actual current wrappers/docs before selecting commands (bin/lovelace before cutover, bin/monolith afterward); never assume target commands exist. Run only under assignment verification authority. Delegated workers leave builds/tests/formatters to the integration owner and name exact gates. Report actual failures and unrun evidence, fix scoped blockers and let the integration owner perform final authorized verification once.

Advisory polish does not expand scope; finish reachable authorized work and report any exact incomplete gate.
